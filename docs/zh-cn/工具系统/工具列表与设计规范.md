# 工具列表与设计规范

## 工具列表
- 文件操作：Read（读取文件）、Edit（编辑文件）、Write（写入文件）
- 终端：Shell
- 技能：Skill（加载技能详情）

当前实现仅有上述五个工具；Stat、Glob、Grep、AskUserQuestion 均为规划中的工具，暂未实现。

## 工具设计规范

工具系统分为两层，职责分离：

### 工具层（定义与实现合一）

每个工具是 `ToolKind` 枚举的一个变体：工具名称与各参数名称是固定值（如 `"shell"`、`"path"`），工具描述与各参数描述均为翻译键（如 `"tool.shell.desc"`、`"tool.shell.param.command.desc"`），执行逻辑直接写在 `run()` 中并调用 core 层原语。

- **定义与实现同处**：工具名称与各参数名称为固定值，工具描述与各参数描述均为翻译键；`ToolKind::run()` 内含具体执行逻辑，不存在独立的 runner 层。
- `ToolParam` 描述一个参数：`name`（参数名）、`kind`（类型提示）、`description_key`（描述翻译键）、`required`（是否必需）、`semantic`（语义分类，见下）。
- 每个参数的 `semantic` 字段标记该值的用途，供审核层泛化判断：
  | 语义 | 用途 | 审核含义 |
  |------|------|----------|
  | `None` | 普通参数 | 无需特殊检查 |
  | `ReadPath` | 读取文件/目录路径 | 工作区内 Allowed；工作区外 NeedsApproval |
  | `WritePath` | 写入文件路径 | 工作区内 Manual → NeedsApproval / AcceptEdit → Allowed；工作区外 NeedsApproval |
  | `Command` | Shell 命令 | 白名单内 Allowed；白名单外 NeedsApproval（危险命令 Denied） |
  | `Content` | 涉及写入/编辑操作的、与工作区内容强相关的字符串 | 始终 Allowed，隐私保护由独立的 sanitize/restore 管线处理 |
- 所有内置工具通过 `all_tools()` 收集，是"哪些工具存在"的唯一真相来源。

### 解析器层

每种调用格式（XML、JSON 代码块、invoke 等）实现 `ToolCallFormatParser` trait：

```rust
pub trait ToolCallFormatParser: Send + Sync {
    fn format_name(&self) -> &'static str;
    fn try_parse(&self, input: &str, tools: &EnabledToolSet) -> Result<ParseOutcome, ParseError>;
    fn tool_call_template(&self, tool: &ToolKind) -> String;
}
```

- **解析与渲染对称设计**：`try_parse()` 将输入文本转为结构化调用，`tool_call_template()` 将工具定义渲染为该格式的标准调用模板。
- **`FormatRegistry`** 管理所有注册的解析器，支持 `AutoDetect`（自动探测）和 `Fixed(format)`（固定格式）模式，线程安全（`RwLock`）。
- 内置三种格式按注册顺序为 `json-codeblock` → `invoke` → `xml`；`AutoDetect` 按该顺序尝试，`/format` 循环顺序为 `auto` → `json-codeblock` → `invoke` → `xml`。

### 核心原则

1. **工具定义不感知格式**：添加新调用格式只需实现一个 trait 并注册，无需修改任何工具。
2. **每个格式自包含**：解析和模板渲染在同一 trait 中，格式的完整知识只存在于一个地方。
3. **工具定义与实现合一，解析器是行为**：新增格式不影响现有工具，新增工具自动被所有格式支持；审核层只依赖 `semantic` 标记，不依赖工具名。
