# 已抛弃的设计与不会实现的需求

以下列出在需求讨论过程中被明确放弃或确认不会出现的特性：

1. **自动化与 LLM 平台交互**：本工具不支持任何自动化请求，不提供 API 密钥管理，不直接调用 LLM API。
2. **多 Agent 协作**：不支持 Agent 间相互调用、委派或通信。
3. **审核超时自动处理**：不存在审核超时概念，用户离开即暂停，不自动通过或拒绝。
4. **后台运行与通知**：程序不支持后台长期运行或桌面通知。
5. **数据库内容加密**：因纯本地应用且参考同类开源工具，暂不考虑数据库加密存储。
6. **工具扩展/插件系统**：暂不支持动态注册自定义工具。
7. **技能版本管理**：技能不支持版本控制。
8. **受限模式（早期）**：先前设计的第二个实例进入“受限模式”被废弃，改为每个实例独立新会话，只警告写锁冲突。
9. **Shell 命令撤销**：不支持 Shell 操作的撤销，仅提供日志记录。
10. **全自动化审核（模型审核指令）**：当前仅由用户人工审核，未来可能增加 API 模型审核，但不属于当前版本。
11. **任务树结构**：任务不支持父子层级或依赖关系。
12. **任务间通信**：不支持。
13. **Git 深度集成工具**：仅通过 Shell 工具调用 git 命令，不提供独立的 Git 操作工具。
14. **文件预览功能**：文件树暂不提供文件内容预览。
15. **记忆文件自动智能管理**：目前由 Agent 和用户手动维护，无自动摘要或清理机制。
16. **导出功能的自动清理**：导出不会自动删除本地数据。
17. **Write工具覆盖/写入大文件压缩**：暂不考虑支持，可通过删除旧会话清理这些旧会话内记录的大文本数据。
18. **Write工具覆盖性写入安全性**：不考虑若外部编辑器在 Write 审核通过后修改了文件，不做任何冲突检测可能带来的问题。该情况可以使用撤销栈回滚。
