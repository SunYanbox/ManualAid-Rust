# 输出规范与回滚

## 工具执行结果输出规范

1. 只读工具：结果覆盖与调用统计
   - 对于只读工具（如文件读取、查询命令等），同一会话内**仅保留最新一次**的执行结果，此前结果将被覆盖。
2. 失败时的错误信息
   - 工具调用失败（非零退出码或执行异常）时，必须返回 **UTF-8 编码**的错误信息，内容直接呈现，方便用户复制并反馈给模型。
3. 空输出的统一处理
   - 若工具正常执行（退出码为 0），但 `stdout` 与 `stderr` 均为空，则统一输出固定提示：
     `(工具正确执行且未输出任何文本)`
   - 该规则适用于所有可能产生空输出的工具（如 Shell 命令、文件读取），避免Agent误以为工具未运行。
   - 对于只读工具，即使结果为空，仍需遵循第 1 条的统计与覆盖规则。
4. 统计
   - 需跟踪并展示单会话内所有的**累计调用次数**与**累计运行时长**，数据储存在数据库中。

## 编辑审核与回滚
- 所有 Edit/Write 调用进入审核队列（按会话独立），在工具记录区域底部依次弹出审核卡片，用户选择同意/拒绝/拒绝并键入文本。
- 审核通过后修改即时写入磁盘。
- **执行前二次校验**：即使是审核通过的 Edit 操作，在最终落盘写入前，系统必须再次读取目标文件，校验 `old_string`（Edit工具的原字符串参数）是否仍然存在于文件中；Write工具是覆盖性的，但当对应位置存在原文件时，在撤销栈/数据库中记录原文件为原字符串，新写入的内容为新字符串。
- **冲突处理**：如果二次校验发现原字符串不存在（例如被外部编辑器修改或删除），系统不进行任何写入操作，直接向用户提示"应用修改失败：原文本已发生变化或不存在"。
- 回滚和重放均基于新旧字符串对比。撤销栈作为工具调用结果的一部分存储，其数据结构需包含（文件路径、原字符串、新字符串），以确保在未被外部破坏的前提下可以精准回滚。
- 撤销与重放支持跨会话持久化，只要对应的会话记录未被清理。当因外部修改导致原切片丢失无法撤销时，按上述冲突处理机制报错。
- 当清理工具调用结果导致某些时间戳前的编辑无法撤销时，UI 信息条会显示截止点。
