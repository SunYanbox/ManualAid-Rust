# 执行与审核层

## 完整调用链

```
用户输入文本
    │
    ▼
┌─ Parser ──────────────────────────┐
│  解析 → ParsedToolCall             │
└──────────┬─────────────────────────┘
           ▼
┌─ Executor ─────────────────────────┐
│  1. 路由：tool_name → ToolKind      │
│  2. 参数校验：params × ToolParam     │
│  3. 权限审核（Auditor）              │
│    ├─ ParamSemantic::ReadPath → 读路径  │
│    ├─ ParamSemantic::WritePath → 写路径 │
│    ├─ ParamSemantic::Command → 白名单   │
│    ├─ ParamSemantic::Content → 隐私  │
│    └─ ParamSemantic::None → 放行    │
│  4. 执行（ToolKind::run）            │
│  5. 结果后处理                      │
└──────────┬─────────────────────────┘
           ▼
    返回执行结果
```

> 3. 权限审核（Auditor）独立于执行层，详见 [权限策略](../权限与审核/权限策略.md)。

### 1. 路由

通过 `ParsedToolCall::tool_name` 在 `all_tools()` 返回的 `ToolKind` 列表中查找匹配的工具。

### 2. 参数校验

`ParsedToolCall::params`（保序参数映射）对照 `ToolKind::parameters()` 做类型和必要性检查：

```rust
// 伪代码示意
for def_param in tool.parameters() {
    match raw.get(def_param.name) {
        None if def_param.required => Err(ParamError::missing),
        None => continue,
        Some(value) => check_type(value, def_param.kind),
    }
}
```

### 4. 执行

每个 `ToolKind` 变体的 `run()` 直接调用 core 层原语：

| 工具 | 底层调用 |
|------|----------|
| Read | 文件读取 + 编码检测 + offset/limit 截断 |
| Edit | `plan_edit` 预验证 → 读取文件 → 查找 `old_string` → 替换 → 写回 |
| Write | 文件写入（自动创建父目录） |
| Shell | `manualaid_core::shell::run_shell`（完整 stdout/stderr/退出码/超时） |

### 关键设计原则

- **审核层不依赖工具名**，仅依赖 `ParamSemantic` 标记——新增工具只要正确标记参数语义，审核自动适配。
- **工具定义与实现合一**，同一个工具可被任意格式调用（XML / JSON / 未来格式），审核逻辑完全复用。
- **执行前二次校验**：Edit 的 `old_string` 在写入前再次核对文件内容，防止并发修改导致冲突。
