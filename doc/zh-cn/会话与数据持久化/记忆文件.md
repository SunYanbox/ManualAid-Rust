# 记忆文件

- Agent 记忆文件位于 `~/.ManualAid/projects/{项目路径标志}/memory/*.md`（关于 `~/.ManualAid/` 详见 [ManualAid文件夹](./ManualAid文件夹.md)），由 Agent 自主维护，也可由用户手动编辑。项目路径标志的构建参考[项目路径标志](./项目路径标志.md)。且`~/.ManualAid/projects/{项目路径标志}/memory/`文件夹下的读写免审核。
- 记忆文件在项目范围内共享，多实例写入时通过文件锁协调。
- 系统提示词构建时会包含记忆文件的头部摘要（`- 记忆名称: 记忆描述 记忆时间等`）。

> 上述所有斜体数据均表示可在配置文件/GUI设置页面中修改
>
> 以下内容即是关于记忆文件夹的设计，也是需要告诉Agent的提示词

记忆文件夹结构

```
memory/
————MEMORY.md # 记忆索引文件
————*.md      # 其他记忆文件
```

`MEMORY.md` 是记忆索引文件，包含项目中所有记忆的目录（文件路径 + 一句话描述 + 创建日期和上次修改日期），由 Agent 自行维护。每次会话启动时，索引文件会加载到上下文供 Agent 检索——每行一条记忆条目，使用无序列表格式，不包含前置元数据，记忆的具体内容放在各自的文件中，不要写入索引文件。

每条记忆是一个独立的 `.md` 文件，记录一个事实或一条知识，文件头部附带 YAML 前置元数据：

```markdown
---
name: <短横线命名法的短名称>
description: <单行摘要，用于回忆时快速判断是否与当前问题相关>
metadata:
  type: user | feedback | project | reference
datetime: <日期和时间>
---

<事实内容>
```

四种记忆类型：
- `user` — 关于用户的信息：身份角色、技术专长、个人偏好与习惯。
- `feedback` — 用户对 Agent 工作方式的反馈：纠正意见、确认的方法或行为偏好，应附上**原因：**和**如何应用：**，说明为什么这样做以及今后如何执行。
- `project` — 项目层面的上下文：进行中的工作、目标、无法从代码或 git 历史中获知的约束；涉及日期的内容应转换为绝对日期。
- `reference` — 外部资源引用：相关 URL、仪表板链接、工单编号等。

在正文中，使用 `[[名称]]` 语法建立记忆之间的关联，其中 `名称` 对应目标记忆文件 `name` 字段的值。即使目标记忆尚不存在，也可以使用未匹配的 `[[名称]]` 作为占位符，标记未来值得记录的内容。

Agent 写入记忆的规则：
- 写入新记忆文件后，同步更新 `MEMORY.md` 索引，添加 `- [标题](file.md) — 说明` 格式的条目。
- 保存前检查是否已有覆盖相同主题的文件——如有则更新已有文件，避免重复；发现内容已不再正确的记忆应予删除。
- 不要保存可从代码库直接获取的信息（代码结构、历史修复、git 历史等）或仅与当前单次对话相关的临时内容。如果用户要求记住此类信息，询问其中哪些是非显而易见的要点，只保存那些部分。
- 系统加载的已召回记忆属于背景上下文，反映的是写入时的状态——如果其中提到某个文件、函数或配置项，在给出建议前应验证其当前是否仍然存在。
