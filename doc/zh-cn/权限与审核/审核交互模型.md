# 审核交互模型

审核不设独立窗口，而是在工具记录区域**内联弹出**。

## 审核触发条件
需要审核的操作包括：
1. 读取工作区外的文件
2. 编辑/写入文件（手动模式下所有编辑/写入均需审核；接受编辑模式下仅工作区外的编辑/写入需审核）
3. Glob/Grep 搜索范围涉及工作区外的路径
4. 执行非白名单 Shell 命令
5. 其他被当前 Agent 工具权限策略标记为需审核的操作

## 内联审核流程
1. 工具调用被解析后，若需审核，在**工具记录与结果**区域（类似聊天框的控件）底部内联渲染审核选项卡片。
2. 审核卡片包含：
   - 操作摘要（文件路径 + 变更行数，或完整命令字符串，长命令显示开头）
   - 三个单选选项：
     - **同意**：执行该操作
     - **拒绝**：拒绝该操作，返回拒绝信息给 Agent
     - **拒绝并键入文本**：在文本输入框输入文本，在确认后将用户键入的文本作为该工具调用的结果返回给 Agent（例如告知 Agent 为什么拒绝、建议替代方案）
3. 当有多个待审核项时，**依次弹出**——当前项审核完成后自动展示下一项。
4. 审核结果记录到会话数据库，持久化保存。
5. 未审核项在程序关闭后重新打开会话时恢复，审核队列保持不变。

### TUI 中的审核交互
- 审核卡片使用高亮边框控件渲染，三个选项通过方向键/数字键/鼠标选择。
- 审核项详情（如完整 Diff、命令完整参数）可通过按键展开查看。

### CLI loop 中的审核交互
- 待审核项由 `Auditor::build_approval_queue` 生成，**逐条弹出**，当前项处理完成后自动展示下一项。
- 每条以文本提示呈现操作摘要（Shell 命令全文，或 Edit/Write 的文件路径与变更信息）。
- 输入 `y` 同意执行；`n` 拒绝并将拒绝信息返回给 Agent；`t` 进入"拒绝并键入文本"，读取一行输入作为该工具调用的结果返回。
- 硬拒绝（`Denied`，如命中危险模式）不进入队列，直接作为工具失败结果返回。

### GUI 中的审核交互
- 审核卡片为工具记录区域底部的内联控件，三个选项通过鼠标点击或键盘快捷键选择。
- "拒绝并键入文本"选中后展开文本输入框。
- 鼠标悬停显示详情 Tooltip，双击打开完整 Diff 弹窗。
