# 隐私掩码与注册表

## 可逆掩码与参数还原

可逆掩码与参数还原的函数组合为 `sanitize_prompt()` 加上 `restore_masked_data()`，方向是**可逆的**。它的用途是，在把提示词发给大语言模型之前，先将敏感数据替换为占位符（比如 `[PRV_EMAIL_1]`）；当大语言模型返回的工具调用中包含这些占位符时，在实际执行前再把占位符还原为原始值。

**关键流程**：

```
工具输出数据含 "jane@example.com"
    │
    ▼
sanitize_prompt() → 扫描 PII → get_or_create("EMAIL", "jane@example.com") → [PRV_EMAIL_1]
    │               替换原文为占位符
    ▼
返回 ("联系 [PRV_EMAIL_1]", {[PRV_EMAIL_1] → "jane@example.com"})
    │
    ▼  （发送给 LLM，LLM 永远不碰真实邮箱）
    │
LLM 返回工具调用：<read><file_path>/contacts/[PRV_EMAIL_1]</file_path></read>
    │
    ▼
executor 查询映射 HashMap → 获取原始值
    → restore_masked_data("[PRV_EMAIL_1]", &映射) → "jane@example.com"
    │
    ▼
Executor 用还原后的真实路径执行 Read
```

**实现位置**：`Executor` 在完成解析和校验后、调用 `ToolRunner` 之前，对 `ParsedToolCall::params` 中的**所有字符串值**执行 `restore_masked_data()` 还原：

```rust
// 伪代码示意：参数还原
fn restore_params(call: &mut ParsedToolCall, mapping: &HashMap<String, String>) {
    for value in call.params.values_mut() {
        if let Value::String(s) = value {
            *value = Value::String(restore_masked_data(s, mapping));
        }
    }
}
```

这样 LLM 永远不接触原始敏感数据，但工具执行时拿到的是真实值。

## 隐私注册表（PrivacyRegistry）

`PrivacyRegistry`确保同一隐私值在整个进程生命周期内映射到**同一稳定的占位符**（如 `[PRV_EMAIL_1]`），避免 LLM 在不同轮次中看到同一邮箱一会儿是 `[PRV_EMAIL_1]`、一会儿是 `[PRV_EMAIL_3]`。

**内存安全**：内存中仅存储明文数据的 SHA-512 哈希值，不存储原始明文。`get_or_create()` 返回的 `MaskId` 由调用方构建临时的 `HashMap<MaskId, Plaintext>`，使用完毕后丢弃。

**当前实现**：进程级内存注册表，跨会话持久化待数据库基础设施就绪后实现。

> 2026/07/25

**计划集成**：

```text
sanitize_prompt(text)
  → scanner.scan(text)                     ← 检测 PII
  → PrivacyRegistry::get_or_create(tag, plaintext)  每个检测项
    → 返回稳定 mask_id（如 [PRV_EMAIL_1]）
  → 替换原文为 mask_id
  → 返回 (masked_text, HashMap<mask_id, plaintext>)

映射传递给 executor，用于 restore_masked_data
```

> **未来扩展**：当数据库层就绪后，`mask_id → 加密明文` 将持久化存储，实现跨会话稳定性。设计见下文 [数据库持久化方案](#数据库持久化方案)。

## 数据库持久化方案

`PrivacyRegistry`（`src/core/privacy_registry.rs`）当前为纯内存实现：

- 内存中仅存储 SHA-512 哈希 → `MaskId` 的映射
- 同一进程内同一明文始终映射到同一占位符
- 进程重启后注册表丢失，占位符重新编号

### 持久化目标

在数据库基础设施就绪后，实现跨会话的稳定映射：

| 存储内容 | 说明 |
|----------|------|
| `mask_id → 加密明文` | 持久化到数据库，密文存储 |
| `SHA512(明文) → mask_id` | 内存中仅存哈希，用于快速去重 |
| 计数器 | 每种实体类型的计数器（如 EMAIL 计数到 42） |

### 设计要点

#### 写入路径

```
sanitize_prompt → get_or_create(entity_type, plaintext)
  → 计算 SHA-512(plaintext)
  → 查内存 hash_to_mask 表
  → 未命中：生成新 mask_id，写入 DB {mask_id → encrypt(plaintext)}
  → 更新内存 hash_to_mask{hash → mask_id}
```

#### 读取路径

```
restore_masked_data(mask_id)
  → 查 DB 获取 mask_id → encrypt(plaintext)
  → 解密 → 得到原始明文
```

#### 内存安全

- `HashMap<Hash, MaskId>` 只存哈希，不存明文
- 明文仅在解密瞬间出现在栈上，用完即弃
- 数据库可使用 SQLite + `sqlcipher` 或类似方案加密

#### 启动加载

进程启动时，从数据库加载全量 `hash → mask_id` 映射到内存：
```
SELECT mask_id, sha512_hash FROM privacy_registry
```
但**不加载明文**到内存。明文在需要时（`resolve`）从数据库按需读取。
