# 提示词设计

> 系统提示词设计经验总结。背景：2026-08-11 提示词优化（路径猜测 / 急于求成 / SKILL 加载 / Shell 过度使用四个问题）过程中，对"约束密度与模型性能"的调研结论。

## 核心结论

系统提示词中**过多严格限制会降低模型对提示词的遵循率**，称为 over-prompting / Instruction Compliance Ceiling（指令遵循天花板）。这不是提示词写法问题，而是 Transformer 注意力机制的固有局限：每条规则与任务上下文竞争注意力权重，规则过多时中间位置的规则最易被忽略（primacy bias）。

## 阈值（研究参考值）

- 每类别 5-7 条高影响约束为最优。
- 单个组件的祈使句（"you must / never / always"）不超过 8 处。
- 系统提示词整体目标 ≤1500 tokens。
- 代码生成任务中约 4 个同时约束后准确率明显下降。
- 高指令密度（约 500 条指令）下，前沿模型遵循率仅约 68%。

## 缓解方式（按优先级）

1. **合并重叠规则**：新增规则前先检查已有规则是否覆盖部分语义，通过合并/替换实现，而不是追加新规则。
2. **模块化**：任务特定规则移入 skill 按需加载；系统提示词只保留适用于所有任务的规则。
3. **工具层强制**：必须生效的规则交给 linter、pre-commit、CI 等机制，不依赖提示词。
4. **分类组织**：同类规则归入独立小节（如 `<path-rules>`、`<verification-rules>`），降低模型检索成本。
5. **工具描述声明**：能写进工具/参数描述（`tools.*.toml`）的约束，不在系统提示词中重复。

## 本项目当前状态（2026-08-11）

- 系统提示词规则总量约 38 条、祈使句约 14 处，已处于研究警告区间，后续添加规则必须通过合并/替换进行。
- 示例：禁止推测工具结果规则通过与"检查退出状态"规则合并实现，净增 0 条规则。

## 未来添加规则的检查清单

- [ ] 是否与现有规则语义重叠？（重叠则合并，而非追加）
- [ ] 是否适用于所有任务？（仅特定任务 → 移入 skill）
- [ ] 能否由工具层或审计层强制？（能 → 不加提示词）
- [ ] 添加后祈使句是否超过 8 处、总规则是否超过 40 条？（超过 → 先精简再加）
