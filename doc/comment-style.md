# 注释风格指南

## 核心原则

解释**为什么**，而非**做什么**。

## 禁止

- 重复代码本身的废话
- 过时或误导的注释
- 注释掉的大段废弃代码
- "日记式"注释（署名、日期）
- 用注释掩盖糟糕的代码（应重构）
- **装饰性分隔线**：`----`、`====`、`── ──` 等

## 文档注释格式

### 模块级（`//!`）

```
//! 一行双语简单描述
//!
//! # Description
//! 英文详细描述。
//! # 描述
//! 中文详细描述。
```

### 函数/结构体（`///`）

简短注释可只用一行双语描述：
```
/// 一行双语简单描述
```

详细注释保留标题结构：
```
/// 一行双语简单描述
///
/// # Description
/// 英文详细描述。
/// # 描述
/// 中文详细描述。
```

## 双语要求

文档注释（`//!` 和 `///`）应同时提供英文和中文，英文在前，中文在后。
